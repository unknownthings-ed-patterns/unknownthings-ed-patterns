# 同期と安全ツール

Obsidian 側とホームページ側を同期するとき、どのツールが何をするかを確認するページ。

## 基本方針

- 自動修正は、既存リンクに基づく逆参照追加を中心にする。
- デフォルトは dry-run。実際に Obsidian 側を書き換えるときだけ `--apply` を使う。
- 重要な書き換え前には、可能なら Obsidian 側の git スナップショットを取る。
- 生成レポートは確認用であり、本文そのものの判断は手で読む。

## ツール別の役割

| ツール | 役割 | 安全上の扱い |
|---|---|---|
| `run-all-fixes.sh` | 既存リンクに基づく逆参照追加だけを順番に実行する | デフォルトは dry-run。`--apply` のときだけ書き換える |
| `setup-vault-git.sh` | Obsidian の wiki フォルダに git を初期化する | 初回だけ使う。以後は自動修正前のスナップショットを取りやすくなる |
| `sync-obsidian.sh` | Obsidian から Quartz の `content` へ同期し、必要な生成・lint・commit・push を行う | 実行前に dry-run の自動修正を走らせ、意図しない本文書き換えを避ける |
| `lint-wiki.mjs` | 文献・リンク・構造の問題を `lint-report.md` に出す | 文献ページテンプレートは文献本文ではないため対象外 |
| `network-report.mjs` | つながりの中心性や孤立気味のページを確認する | レポートは同期対象から除外し、判断材料として使う |

## `run-all-fixes.sh` がやること

1. ハブパタンへの逆参照を確認する。
2. 文献から Wiki への逆参照を確認する。
3. 実践からパタンへの逆参照を確認する。
4. 概念からパタンへの逆参照を確認する。
5. その他ディレクトリからパタン・文献への逆参照を確認する。

除外しているもの:

- 孤立リンクの移動
- 引用対応表による文献追加
- 出典セクションの自動追加

## 使うときの目安

| やりたいこと | 使うもの |
|---|---|
| 何が直りそうかだけ見る | `./run-all-fixes.sh` |
| 逆参照追加を実際に反映する | `./run-all-fixes.sh --apply` |
| Obsidian からホームページ側へ同期する | `./sync-obsidian.sh` |
| Obsidian 側の書き換え前スナップショットを有効にする | `./setup-vault-git.sh` |
